# Authoring a component

Each component lives in `src/components/<Name>/` and contains exactly these files:

<table>
  <thead>
    <tr><th>File</th><th>Purpose</th></tr>
  </thead>
  <tbody>
    <tr><td><code>{"<Name>.tsx"}</code></td><td>The component. It wraps a React Aria Components primitive and is styled with StyleX.</td></tr>
    <tr><td><code>{"<Name>.docs.ts"}</code></td><td>The documentation contract (<code>{"defineComponentDocs"}</code>), shared by Storybook, AI agents and Figma.</td></tr>
    <tr><td><code>{"<Name>.stories.tsx"}</code></td><td>Stories. Pass <code>{"parameters: { themis: docs }"}</code>. Stories are also browser tests.</td></tr>
    <tr><td><code>{"index.ts"}</code></td><td>Public exports. Also re-export these from <code>{"src/index.ts"}</code>.</td></tr>
  </tbody>
</table>

## Rules

1. **Start from React Aria.** If a RAC component exists, wrap it. Do not reimplement keyboard handling, focus or ARIA.
2. **Style interaction states through RAC render props.** Use `racStyles()` from `src/utils/stylex-rac.ts`, not StyleX `:hover` or `:focus`.
3. **Use tokens only.** Import variables from `src/tokens/*.stylex.ts`. Prefer semantic tokens, and never hard-code colors.
4. **Write JSDoc on every prop.** It becomes the prop table, the Storybook manifest and the Figma manifest.
5. **Keep docs in sync.** List every token the component uses in `tokens` and every Figma property in `figma.properties`.
   `npm run manifest` fails when any of them refers to something that does not exist.
6. **Write one story per meaningful state.** Add `play` functions for behavior. Every story runs axe, and a violation fails `npm test`.
7. **Use `xstyle` for layout only.** Consumers may set margin, flex and grid placement through it, never color or type.
8. **Reuse the shared interaction helpers** in `src/utils/` instead of restyling states by hand:

   | Helper | What it does | Uses |
   | --- | --- | --- |
   | `focusRing` (`focus-ring.ts`) | 2px black/white dashed ring outside the element. See Foundations / Focus ring. | The element's `outline` and `::before` |
   | `touchTarget` (`touch-target.ts`) | 44×44px touch area on touch screens. See Foundations / Touch targets. | The element's `::after` |
   | `pressMotion` (`press-motion.ts`) | Shrinks the visible layers to `scale.pressed` while pressed. See Foundations / Motion. | The Surface's `transform` |
   | `interactiveCursor` (`interactive-cursor.ts`) | `pointer` when enabled, `not-allowed` when disabled, `progress` while pending. | The element's `cursor` |

   Hover and press colors come from tokens, not helpers: a filled Surface's hover is its solid `*-hover` token
   (`brand-hover`, `state.error-hover`…), and anything transparent or `background`-colored gets the tone's see-through
   `*-tint` (`brand-tint`, `background-hover`, `inverse-tint`…). Draw it on the Surface's `::before` and fade its
   opacity. Add each new text-on-hover pair to `tokens/contrast-pairs.json`.

   Every clickable control uses `interactiveCursor`. The exceptions are elements with their own conventional
   cursor: text inputs (`text`), draggable items (`grab`/`grabbing`), resize handles and the like.

   Keep the clickable element and the visible Surface separate, as Button does: the element never changes size,
   and the Surface carries the fill, State Layer and press shrink. Document what the component animates in the
   docs' `motion` field.
