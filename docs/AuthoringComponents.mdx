# Authoring a component

Each component lives in `src/components/<Name>/` and contains exactly these files:

| File | Purpose |
| --- | --- |
| `<Name>.tsx` | The component. It wraps a React Aria Components primitive and is styled with StyleX. |
| `<Name>.docs.ts` | The documentation contract (`defineComponentDocs`), shared by Storybook, AI agents and Figma. |
| `<Name>.stories.tsx` | Stories. Pass `parameters: { themis: docs }`. Stories are also browser tests. |
| `index.ts` | Public exports. Also re-export these from `src/index.ts`. |

## Rules

1. **Start from React Aria.** If a RAC component exists, wrap it. Do not reimplement keyboard handling, focus or ARIA.
2. **Style interaction states through RAC render props.** Use `racStyles()` from `src/utils/stylex-rac.ts`, not StyleX `:hover` or `:focus`.
3. **Use tokens only.** Import variables from `src/tokens/*.stylex.ts`. Prefer semantic tokens, and never hard-code colours.
4. **Write JSDoc on every prop.** It becomes the prop table, the Storybook manifest and the Figma manifest.
5. **Keep docs in sync.** List every token the component uses in `tokens` and every Figma property in `figma.properties`.
   `npm run manifest` fails when any of them refers to something that does not exist.
6. **Write one story per meaningful state.** Add `play` functions for behaviour. Every story runs axe, and a violation fails `npm test`.
7. **Use `xstyle` for layout only.** Consumers may set margin, flex and grid placement through it, never colour or type.
